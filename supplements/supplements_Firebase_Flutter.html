Firebase avec Flutter :

Introduction :

Ce syllabus constitue un parcours complet destiné à accompagner la conception et le développement d'une application Flutter multiplateforme sécurisée, reposant sur les services Firebase.

L'objectif est de construire progressivement une application capable de fonctionner sur Android, iOS et PC/Web, tout en utilisant une infrastructure Firebase commune pour l'authentification, la gestion des utilisateurs, le stockage des données et la sécurité.

La formation commence par la mise en place de l'environnement de développement et la configuration de Firebase. Elle évolue ensuite progressivement vers la création d'un système d'authentification complet et sécurisé.

Une attention particulière est consacrée à la sécurité des comptes utilisateurs. Le parcours comprend notamment :

  • la création d'un compte avec une adresse email et un mot de passe;

  • la vérification de l'adresse email;

  • la vérification du numéro de téléphone par SMS;

  • l'utilisation de l'authentification multifacteur (MFA);

  • l'intégration de Google Authenticator;

  • la gestion des sessions et des différents états d'un compte;

  • la protection des écrans et des fonctionnalités de l'application;

  • la gestion des données avec Cloud Firestore;

  • la mise en place de règles de sécurité Firebase;

  • la gestion des utilisateurs et des administrateurs;

  • la protection contre les accès non autorisés;

  • l'utilisation de Firebase App Check;

  • la mise en place de fonctions backend sécurisées.

Chaque module est conçu pour être suivi progressivement. Les concepts sont expliqués avant leur mise en pratique, puis accompagnés des éléments nécessaires à leur intégration dans le projet : architecture, organisation des fichiers, configuration et code source.

L'objectif final est d'obtenir une application dont la sécurité ne repose pas uniquement sur le code Flutter, mais sur une architecure complète combinant Flutter, Firebase Authentication, Cloud Firestore, Security Rules, App Check et backend sécurisé.

Ce syllabus doit ainsi servir à la fois de cours, de guide de développement et de référence technique, permettant de construire le projet étape par étape et de revenir facilement sur chaque partie lors de son évolution ou de sa maintenance.

Module 1 : Configuration Firebase :

Présentation du module :

Après avoir créer notre application Flutter, nous allons maintenant connecter cette application à Firebase.

L'objectif est de comprendre non seulement comment connecter Firebase à Flutter, mais également pourquoi chaque étape est nécessaire, comment organiser les environnements et comment préparer proprement le projet pour les modules suivants.

À la fin de ce module, l'application Flutter sera connectée à un projet Firebase et pourra progressivement utiliser les différents services Firebase.

L'architecture commencera alors à évoluer vers :

Les services ne seront pas tous activés immédiatement. Ils seront introduits dans les modules correspondants.

Objectifs du module :

Qu'est-ce que Firebase ?

Firebase est une plateforme de services backend permettant de fournir à une application différentes fonctionnalités sans devoir développer soi-même l'intégralité de l'infrastructure serveur.

Dans notre projet, Firebase pourra notamment fournir :

  • authentification;

  • base de données Firestore;

  • stockage de fichiers;

  • fonctions backend;

  • sécurité;

  • vérification d'applications;

  • monitoring;

  • services associés au développement et à la production.

L'architecture générale sera progressivement :

                 APPLICATION FLUTTER
                         │
                         ▼
                  FIREBASE SDK
                         │
          ┌──────────────┼──────────────┐
          │              │              │
          ▼              ▼              ▼
   Authentication    Firestore       Storage
          │              │              │
          └──────────────┼──────────────┘
                         │
                         ▼
                 Security Rules
                         │
                         ▼
                   App Check
                         │
                         ▼
                  Backend sécurisé

Pourquoi utiliser Firebase ?

Dans ce projet, Firebase permet de construire progressivement une infrastructure backend complète.

Sans Firebase, il faudrait notamment développer et maintenir :

  • un serveur;

  • une base de données;

  • un système d'authentification;

  • un système de gestion des sessions;

  • des API;

  • une infrastructure de stockage;

  • des mécanismes de sécurité;

  • des systèmes de monitoring.

Firebase permet de disposer d'une grande partie de cette infrastructure sous forme de services intégrables dans Flutter.

Cependant, Firebase ne signifie pas automatiquement que l'application est sécurisée.

La sécurité devra être conçue séparément.

C'est pourquoi le parcours abordera ensuite :

Firebase

Authentication
   +
Security Rules
   +
App Check
   +
Backend sécurisé

Projet Flutter et projet Firebase :

Une notion fondamentale doit être comprise avant de commencer.

Le projet Flutter et le projet Firebase sont deux éléments différents.

Projet Flutter
     │
     │ configuration
     ▼
Projet Firebase
     │
     ├── Android
     ├── iOS
     ├── Web
     └── autres plateformes

Le projet Flutter contient le code de l'application.

Le projet Firebase contient l'infrastructure backend associée.

La configuration permet de faire le lien entre les deux.

Création du projet Firebase :

La première étape consiste à créer un projet Firebase.

Le projet devra avoir un nom identifiable. Par exemple : secure-flutter-app.

Il est conseillé d'utiliser un nom cohérent avec le projet Flutter.

Le nom du projet Firebase servira ensuite d'identifier l'infrastructure backend.

Projet Firebase de développement :

Pour une application sérieuse, il est recommandé de distinguer les environnements.

Une organisation possible sera :

Flutter
│
├── Development
│      │
│      └── Firebase Development
│
└── Production
       │
       └── Firebase Production

Le projet de développement servira aux essais.

Le projet de production contiendra les données réelles.

Cette séparation deviendra particulièrement importante lorsque nous travaillerons avec :

  • Firestore;

  • utilisateurs;

  • Security Rules;

  • Cloud Functions;

  • Storage;

  • déploiement.

Comprendre les applications Firebase :

Un même projet Firebase peut être associé à différentes applications.

Par exemple :

Projet Firebase
│
├── Application Android
│
├── Application iOS
│
├── Application Web
│
└── autres applications selon les plateformes

Cela permet de connecter différentes versions de l'application au même environnement Firebase.

Cependant, chaque plateforme possède ses propres informations de configuration.

Installation de Firebase CLI :

Firebase CLI permet d'interagir avec Firebase depuis le terminal.

Il sera utilisé notamment pour :

  • gérer certains projets Firebase;

  • utiliser les outils Firebase;

  • déployer certains éléments;

  • gérer les émulateurs;

  • travailler avec les services Firebase;

  • automatiser certaines opérations.

Après installation, il faut vérifier son fonctionnement avec une commande de version.

firebase --version

Connexion à Firebase CLI :

Une fois Firebase CLI installé, il faudra connecter le compte Firebase utilisé pour le projet.

La connexion se fait depuis le terminal.

firebase login

Le navigateur permettra ensuite d'autoriser l'accès au compte.

Il faudra utiliser le compte possédant les droits nécessaires sur le projet Firebase.

Vérification des projets Firebase :

Une fois connecté, il sera possible de vérifier les projets accessibles depuis le compte.

firebase projects:list

Cette commande permet notamment de vérifier :

  • que la connexion fonctionne;

  • que le projet Firebase existe;

  • que le compte possède les autorisations nécessaires.

Installation de FlutterFire CLI :

FlutterFire CLI est l'outil permettant de faciliter la configuration des applications Flutter avec Firebase.

Il permet notamment de générer automatiquement une partie de la configuration nécessaire pour les différentes plateformes.

L'installation se fera via Dart avec la commande suivante :

dart pub global activate flutterfire_cli

Une fois installé, il faudra vérifier que l'outil est disponible :

flutterfire --version

Pourquoi utiliser FlutterFire CLI ?

Il serait possible de configurer manuellement chaque plateforme.

Cependant, cela augmenterait le risque :

  • de mauvaise configuration;

  • de fichier manquant;

  • de configuration incohérente entre plateformes.

FlutterFire CLI permet de centraliser une grande partie de cette configuration.

Le processus général sera :

Projet Flutter
      │
      ▼
FlutterFire CLI
      │
      ▼
Sélection du projet Firebase
      │
      ▼
Configuration des plateformes
      │
      ▼
firebase_options.dart

Configuration du projet Flutter avec FlutterFire :

Depuis la racine du projet Flutter, nous utiliserons :

flutterfire configure

L'outil permettra de sélectionner :

  • le projet Firebase;

  • les plateformes concernées;

  • les applications Firebase correspondantes.

Il générera ensuite les éléments de configuration nécessaires.

Le fichier firebase_options.dart :

Un fichier important sera généré :

lib/firebase_options.dart

Ce fichier contient la configuration nécessaire pour initialiser Firebase sur les différentes plateformes configurées.

La structure sera conceptuellement proche :

lib/
│
├── main.dart
├── firebase_options.dart
│
├── app/
├── core/
├── features/
└── shared/

Ce fichier sera utilisé lors de l'initialisation de Firebase.

Comprendre firebase_options.dart :

Le fichier firebase_options.dart contient des informations permettant à l'application de savoir à quel environnement Firebase elle doit se connecter.

Il peut notamment contenir des informations différentes selon la plateforme.

Conceptuellement :

Android
   ↓
Configuration Firebase Android

iOS
   ↓
Configuration Firebase iOS

Web
   ↓
Configuration Firebase Web

Le fichier généré ne doit pas être modifié manuellement sans raison.

Il est préférable de régénérer la configuration avec FlutterFire lorsque la configuration Firebase change.

Initialisation de Firebase :

Après avoir configuré Firebase, il faut initialiser Firebase au démarrage de l'application.

Le principe sera d'utiliser Firebase Core.

Le fichier main.dart évoluera progressivement.

Exemple :

import 'package:firebase_core/firebase_core.dart';
import 'package:flutter/material.dart';

import 'firebase_options.dart';

Future<void> main() async {
    WidgetsFlutterBinding.ensureInitialized();

    await Firebase.initializeApp(
        options: DefaultFirebaseOptions.currentPlatform,
    );

    runApp(const MyApp());
}

Cette étape est fondamentale.

Elle permet à l'application Flutter d'initialiser Firebase avant d'utiliser les services Firebase.

Pourquoi WidgetsFlutterBinding.ensureInitialized() ?

Avant d'exécuter certaines opérations Flutter asynchrones avant runApp(), il faut d'assurer que le binding est correctement initialisé.

C'est notamment nécessaire dans notre cas puisque nous allons initialiser Firebase avant de lancer l'application.

Le principe est :

Démarrage
   │
   ▼
Initialisation Flutter
   │
   ▼
Initialisation Firebase
   │
   ▼
runApp()
   │
   ▼
Application

Firebase Core :

Firebase Core constitue le point d'entrée commun permettant d'initialiser Firebase dans l'application.

Le package sera ajouté au projet via la commande suivante :

flutter pub add firebase_core

Dans pubspec.yaml, on retrouvera progressivement :

dependencies:
    flutter:
        sdk: flutter
    
    firebase_core: ...

La version exacte du package devra être déterminée par la version de Flutter utilisée au moment du développement.

Après modification du fichier :

flutter pub get

Vérification de l'initialisation :

Une fois Firebase initialisé, l'application devra être exécutée.

flutter run

L'objectif est de vérifier que :

  • l'application démarre;

  • Firebase s'initialise correctement;

  • aucune erreur de configuration n'apparaît;

  • la plateforme ciblée est correctement reconnue.

Configuration Android :

Android nécessite une configuration spécifique.

FlutterFire permettra de générer la confrontation correspondant à l'application Android.

Il faudra notamment vérifier que l'identifiant de l'application Android est cohérent.

Exemple conceptuel :

com.example.secure_flutter_app

Dans une véritable application, cet identifiant devra être choisi soigneusement car il sera utilisé pour identifier l'application Android.

Application ID Android :

L'Appication ID Android constitue l'identifiant unique de l'application.

Il est important de ne pas le modifier sans comprendre les conséquences.

Il sera notamment lié à :

  • Firebase;

  • Google services;

  • la publication Android;

  • certaines fonctionnalités d'authentification.

Le syllabus expliquera donc la différence entre :

Nom du projet
        ≠
Nom affiché de l'application
        ≠
Application ID Android

Configuration iOS :

iOS possède également son propre identifiant d'application.

On parle notamment de Bundle Identifier.

Exemple conceptuel :

com.example.secureFlutterApp

Il faudra maintenir une correspondance cohérente entre :

Flutter
   │
   └── iOS Bundle Identifier
             │
             ▼
        Firebase iOS App

La configuration iOS nécessitera également un environnement macOS pour la compilation et les tests natifs iOS.

Configuration Web :

La configuration Web fonctionne différemment d'Android et d'iOS.

Firebase sera initialisé à partir de la configuration Web générée.

FlutterFire permettra de gérer cette configuration.

L'application pourra ensuite être lancée avec :

flutter run -d chrome

Cette étape sera particulièrement utile pour vérifier que Firebase fonctionne sur plusieurs plateformes.

Sécurité de la configuation Firebase :

Une confusion fréquente consiste à considérer les informations présentes dans la configuration Firebase comme des secrets.

Il faut distinguer :

Configuration Firebase
        ≠
Secret backend

Certaines informations utilisées pour les applications clientes sont destinées à êrte distribuées avec l'application.

La sécurité ne doit donc pas reposer sur le fait de cacher simplement la configuration Firebase.

La véritable protection reposera notamment sur :

  • Authentication;

  • Security Rules;

  • App Check;

  • contrôle des permissions;

  • backend sécurisé;

  • gestion correcte des secrets côté serveur.

Cette distinction sera essentielle dans les modules de sécurité.

Ce qui ne doit jamais être placé dans l'application cliente :

Les secrets réellement sensibles ne doivent pas être intégrés directement dans le code Flutter.

Par exemple :

  • clés privées;

  • secrets d'administration;

  • credentials de serveur;

  • clés privées de services backend;

  • tokens permanents privilégiés.

Ces éléments devront être conservés côté serveur ou dans des systèmes adaptés de gestion des secrets.

Erreurs corrantes :

Plusieurs erreurs peuvent apparaître lors de la configuration.

Firebase CLI non reconnu :

Exemple :

firebase: command not found

Cela indique généralement que Firebase CLI n'est pas correctement installé ou accessible depuis le PATH.

FlutterFire non reconnu :

Exemple :

flutterfire: command not found

Il faudra vérifier l'installation de FlutterFire CLI et la configuration du PATH.

Mauvais projet Firebase :

Il est possible de connecter accidentellement le projet Flutter à un mauvais projet Firebase.

Il faudra donc toujours vérifier :

Projet Flutter
        │
        ▼
Projet Firebase sélectionné

Mauvais identifiant Android :

Si l'Application ID ne correspond pas à celui configuré dans Firebase, certaines fonctionnalités peuvent ne pas fonctionner correctement.

Mauvais Bundle Identifier iOS :

Même problème côté iOS avec le Bundle Identifier.

Firebase non initialisé :

Si Firebase.initializeApp() n'est pas exécuté correctement, les services Firebase ne pourront pas être utilisés normalement.

Configuration générée obsolète :

Si la configuration Firebase change, il faudra parfois relancer flutterfire configure afin de régénérer les fichiers nécessaires.
